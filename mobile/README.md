# Cosigna mobile — first preview

An Android-first React Native app using Expo SDK 57, with Android/iOS source support. Shopping
and travel remain fictional local examples. A separate **connected order lab** now pairs with
the computer over Android USB forwarding, records an optional voice request, reviews an exact
quote and calls the existing Rust budget/approval service and test merchant. It supports
simulated payments or Stripe sandbox; no real funds or physical orders.

**For tonight's Nokia test, follow [the phone setup guide](../docs/PHONE_VOICE_TEST.md).**
For a bundled APK, Android Studio project, emulator and single-command test runtime, use
[Android Studio setup](ANDROID_STUDIO.md). The generated Google Assistant entry point still
needs Google's account-bound test preview and device validation; Gemini, Swiggy and Zomato
are not connected. Hosted transcription and
optional AI planning require a server-side key and separate consent. No provider key
is persisted by the mobile app. Only the scoped, expiring pairing session is saved encrypted;
recording/provider consent and quote approval are not persisted.

For Groq voice and planning, run `npm run dev:mobile:groq` in `testbeds/voice-merchant` with
`COSIGNA_GROQ_API_KEY` set only on the computer. The app names Groq in its separate audio and
planning consent switches. OpenAI remains available via `dev:mobile:ai`; no automatic
provider fallback occurs. See the phone guide for hidden key entry and the real Groq/Stripe
diagnostic (`npm run check:groq`). Free Groq access is quota limited, not guaranteed capacity.

## Run on your iPhone or Android phone

1. Install an Expo Go release compatible with SDK 57. Check https://expo.dev/go if the store
   release expects a different SDK. This section runs the local fixture examples.
2. For iPhone, sign in to Expo Go with the **same Expo account** shown by `npx expo whoami` in
   PowerShell. In Expo Go, tap the avatar. If the CLI says `Not logged in`, run `npx expo login`
   and follow the browser sign-in. The current iOS Expo Go release requires both sign-ins.
   Android does not require sign-in to run locally.
3. Put the computer and phone on the same trusted Wi-Fi network.
4. In PowerShell:

   ```powershell
   cd C:\Users\Harsha\Pictures\project\mobile
   npm start
   ```

5. On iPhone, scan the QR code with the Camera app and open it in Expo Go. On Android, scan
   it from Expo Go. Keep the terminal running.
   The desktop console does not need to run. There is no console access token to copy.
6. Open Shopping or Travel, compare options, review, then confirm a **demo** approval.
   Try success, price change, and timeout/status lookup. Activity shows the local decisions;
   Controls can reset both examples after confirmation.

Dependencies are installed in this checkout. On a fresh checkout, run `npm ci` first.
`npm run android` generates/builds the native Android application and opens an emulator or
attached device; it requires Android SDK/JDK setup. Native directories are generated by Expo
prebuild and ignored by Git; use config/plugins for native changes. `npm start` with Expo Go
does not require a local Android SDK. The USB helper does require ADB Platform-Tools.
If the phone cannot reach Metro, check the same-network connection and Windows Firewall's
private-network permission for Node; do not disable the firewall or expose the finance console.
No tunnel or cloud deployment is started by these scripts.

## What works

To test the connected voice/Stripe sandbox flow without USB on the same trusted Wi-Fi,
run `npm run start:wifi`. Enter the Groq key only in the launcher's hidden prompt, scan
Expo Go's QR, and pair with a six-digit code from the computer's `http://127.0.0.1:3097`
page. This opt-in local relay exposes only the paired mobile API; see the
[Wi-Fi instructions](../docs/PHONE_VOICE_TEST.md). It is not a public deployment.

Connected order lab:

- One-use pairing, encrypted expiring device session, computer revocation and disconnect.
- Budget creation/revocation and server-backed task recovery; exact-quote owner approval
  goes through the Rust service. Merchant/model/payment credentials stay on the computer.
- Explicit audio-transcription consent, press-to-record, 20-second native capture limit,
  transcript editing and separate planning/approval actions. Fixture planning works typed
  without a provider account. Optional hosted planning has its own consent gate.
- Optional **Start voice checkout**: automatic turn capture/transcription/planning, spoken
  clarifications and exact quote readout, then a fresh “Confirm my order” or “Cancel”.
  Each turn ends after a pause or 12 seconds. Consent, active allowance, foreground state,
  unexpired quote/digest and measured audio activity guard spoken submission. This is test
  intent from a paired phone, not verified voice identity. Manual approval remains available.
- Inline **Your answer** / **Send answer** and voice replies in needs-input requests retain
  the original request and merchant question for planning; replies do not approve purchases.
- Cache recording cleanup is attempted after transcription/discard/background; force-closing
  may leave cache audio. Submitted text/payment evidence remain on the computer. Disconnect
  does not erase those records. No voiceprint, contacts or location access.
- Pending/uncertain submission requires recovery; the app does not retry approval automatically.
- Optional spoken results, merchant fulfillment updates and Stripe test PaymentIntent IDs.

Pair with the six-digit code from the computer browser; it expires after five minutes or
five failed attempts. Updates from the old long-code API require a server restart and re-pair.

The paired API `cosigna.mobile-lab/v3` is a **single-owner development session**, not production
identity, multi-user isolation, automatic delegated spending or a live wallet. The phone cannot
mark merchant orders ready/collected. HTTPS remote access and personal-data deletion controls
are not implemented. All phone features still need physical device validation.

Local shopping/travel fixtures:

- Native task, activity and controls screens with Expo Router navigation.
- Editable per-task budgets, offer selection and requirement checks.
- Exact proposal review and separate simulated confirmation.
- Changed prices clear approval; stale or repeated confirmation cannot complete another task.
- Unknown outcomes stay unresolved until a simulated lookup, without a second submission.
- Android Back returns from review to options; backgrounding dismisses unfinished confirmation.
- Accessible control names, flexible layouts, safe areas, keyboard handling and reduced motion.
- Progress survives navigation within the current app process, but resets on reload/termination.

The fixture reducer was initially based on `console/src/lib/task-fixtures.ts` and has its own
version check on confirmation. It is separate from the connected lab's server authority.
No client reducer is an authority boundary. INR, route and provider names in the fixtures
are example content, not a chosen launch market. The connected cafe lab uses USD.

## Automated checks

```powershell
npm run typecheck
npm run lint
npm test
npm run test:ios
npm run doctor
npm run bundle:android
npm run bundle:ios
```

Tests run with Jest and React Native Testing Library. Native modules are
mocked: these tests establish UI/state behavior, not actual device rendering, VoiceOver/TalkBack
usability, biometric security, merchant integration or payment correctness. The Android and
iOS exports produce JavaScript bundles under `dist`; **they are not installable apps**.

## Standalone APK path

`eas.json` includes an internal-distribution APK profile. Once the Expo account, application
ownership and signing setup are chosen, a signed preview can be built with:

```powershell
npx eas-cli@latest build --platform android --profile preview
```

This command uploads source to Expo's build service and requires account/project setup. It
has not been run. No signing key, cloud project, store listing or release has been created.
`com.cosigna.preview` is a provisional identifier for internal testing, not a production ID.
The generated template icons are not final product artwork.

## Device checks still required

Test on the physical iPhone: QR launch, narrow screen and landscape, large font size, VoiceOver
reading order, keyboard dismissal, gesture navigation, confirmation cancel/background behavior,
and app kill/relaunch. Test Android Back on an Android phone. Run both tasks through all three
simulated outcomes. Confirm fixtures request no microphone/location/contact permissions.
The connected lab must request the microphone only after recording is pressed and use no
location/contacts. Follow the additional failure/recovery checklist in the phone setup guide.

## Dependency audit

The SDK 57 lockfile currently reports 57 npm audit advisories (8 moderate, 49 high) across the
dependency tree, including Expo/React Native tooling. Expo Doctor checks compatibility, not
security advisories. Avoid `npm audit fix --force`, which can introduce breaking Expo downgrades.
Triage the advisories against the intended release build and resolve relevant findings before
distribution.
