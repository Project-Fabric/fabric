A useful agent needs a clear boundary.

AI can interpret a request, compare options, and propose the next action. Moving money adds another question: who authorized it, and within which limits?

Cosigna is being built around that question. The goal is a common control layer for agent-initiated transactions, with the user’s authority visible from request to outcome.

One Cosigna. Several ways to use it.

01

The gateway

The transaction foundation: scoped agents, budgets, exact approval, durable submission claims, and recovery.

02

The console

A workspace for requests, decisions, and records. The current preview uses fixtures and its own sign-in boundary.

03

The assistant

A voice and text interface above the gateway. A local coffee-ordering prototype demonstrates the interaction; broader merchant access is still in development.

04

The developer tools

CLI and tool-gateway components provide controlled execution and history. Their code is being consolidated in stages behind the same Cosigna identity.

Built in small, verifiable steps.

The current focus is the gateway. Local pipelines exercise permissions, approval, budget accounting, repeat requests, and recovery after process termination. A separate merchant API and Stripe sandbox provide controlled purchase and refund experiments.

Product identity is unified. Technical consolidation continues: the consent service and purchase ledger still have distinct implementation paths. A shared authoritative permission contract is a prerequisite for production use.

Cosigna is a developer preview. Test payments demonstrate behavior; they are not customer revenue, a live merchant network, or a production security certification.

What guides the build.

  • Authority comes from an authenticated owner and explicit scope.
  • Model output is a proposal. Code checks the transaction boundary.
  • Uncertainty stays visible until the outcome can be verified.
  • Claims should be tied to reproducible tests and their limitations.
